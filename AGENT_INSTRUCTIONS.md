## 🎯 Agent Mission & Guardrails

Your mission is to maintain and extend a **reliable, local-first macOS assistant runtime**. When implementing new features, modifying tools, or troubleshooting code, you must adhere to the following principles:

1. **Closed-Loop Verification**: A tool call must be verified programmatically, not estimated by LLM vibes. Every state-changing tool should have a verification gate.
2. **Minimal Allowlists**: Keep specialists highly focused. Only grant a specialist the exact tools it needs to succeed.
3. **Safety First**: Irreversible actions, payments, or form submissions must be blocked in code or require human-in-the-loop terminal approvals. Never rely on the model to "be safe" via prompting.
4. **Local by Default**: Ensure all features are designed to work with local models (e.g., `qwen3:8b`) first, using clean JSON schema definitions and minimal token usage.

## 🗺️ Workspace Map

Here is where core systems live:

- **`agent.py`**: The primary orchestrator. Handles the main **Plan → Act → Reflect** loop. Runs specialists based on [specialists.toml](file:///Users/h/OllamaTest/specialists.toml).
- **`mac_agent.py`**: The minimal standalone core. Contains default tool calling configurations and AppleScript automation.
- **`tools.py`**: The registry of all tools. Tools are simple Python functions registered with standard docstrings (which act as descriptions for the LLM).
- **`backends.py`**: Normalizes communication across LLM providers (Ollama, Anthropic, OpenAI, Gemini, Nvidia). Corrects API wire format differences.
- **`config.py`**: Central Pydantic config. Custom parameters can be overridden using `SCREEN_AGENT_*` env variables.
- **`trace.py` / `trace_viewer.py`**: The trajectory logging framework. Generates a standalone visual HTML waterfall of the run.
- **`judge.py`**: Evaluates run trajectories along four dimensions: goal, efficiency, discipline, and safety.
- **`skills.py`**: Retains and feeds worked examples (plans/actions of passing runs) back into the prompt context.
- **`bench/runner.py`**: Run evaluation suites defined in `bench/suites/core.toml`.

## 🛠️ Operating Procedures for Agents

### 1. Verify Setup
Before running any code or agent execution commands, verify the workspace dependencies:
```bash
python scripts/check_setup.py
```

### 2. Standard Coding Workflows
- **To Add a Tool**:
  1. Write the tool function in [tools.py](file:///Users/h/OllamaTest/tools.py) with descriptive docstrings.
  2. Implement an evaluation verify gate (`verify_...` function) that queries the OS state (e.g. using AppleScript or file checks) to confirm the tool's success.
  3. Register the tool in `TOOLS` in `tools.py`.
  4. (Optional) Add the tool to a specialist allowlist in [specialists.toml](file:///Users/h/OllamaTest/specialists.toml).
- **To Debug Trajectories**:
  Check if a task run created a trajectory in `traces/run_<timestamp>.jsonl`. Rerun the trace viewer to produce an HTML timeline and inspect errors:
  ```bash
  python trace_viewer.py traces/run_<timestamp>.jsonl
  ```

### 3. Verify Changes via Benchmarking
Before submitting a change, run the test/eval suite to ensure no regressions:
- **Dry Run (CI-safe, mock tools/models)**:
  ```bash
  python bench/runner.py
  ```
- **Live Run (executes actual commands on macOS)**:
  ```bash
  python bench/runner.py --live
  ```
- **Golden Set (replays historically failed runs to check fixes)**:
  ```bash
  python bench/runner.py --golden
  ```

## ⚠️ Important Agent Development Constraints

- **Do Not Poll**: Never run background commands that poll or sleep in a loop while waiting for external processes. Rely on event listeners or callbacks where possible.
- **AppleScript Execution**: AppleScript is run via the `osascript` CLI wrapper. Keep AppleScripts simple and double-quote strings carefully. Escape characters where appropriate.
- **Playwright CDP**: If you modify web tools, remember that Playwright connects via `connect_over_cdp` to an existing Chrome instance on port `9222`. Ensure clean resource closing by utilizing `cleanup_playwright()` in execution blocks.
- **Tokens and Logging**: Keep LLM prompts concise. Ensure the accessibility tree generated by `page_snapshot.py` is minimized by filtering out occluded nodes before passing it to the context window.
